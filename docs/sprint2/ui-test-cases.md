## วิธีทดสอบ

**1. Component Test Suite (อัตโนมัติ)** — `frontend/tests/booking-ui.test.mjs`
```bash
node --test frontend/tests/booking-ui.test.mjs
```
ใช้ DOM จำลองแบบเดียวกับ `ticket-ui.test.mjs` เรียก component ตรง ๆ ไม่ต้องเปิดเบราว์เซอร์

**2. ทดสอบด้วยมือ — โหมดข้อมูลจำลอง** (ไม่ต้องรัน backend)
```bash
cd frontend
python -m http.server 8080
```
เปิด `http://localhost:8080/?mock=1#/booking` → ล็อกอินด้วยบัญชีทดสอบ

### หมายเหตุ

1. **M-06, M-07 — ข้อความยังกว้างเกินไป:** ระบบไม่ยอมจองถูกต้อง แต่ข้อความ "ข้อมูลที่กรอกไม่ถูกต้อง กรุณาตรวจสอบอีกครั้ง" ไม่บอกว่าช่องไหนผิด (server ส่งข้อความเฉพาะมา เช่น "กรุณากรอกชื่อผู้จอง" / "เวลาสิ้นสุดต้องอยู่หลังเวลาเริ่มต้น" แต่ `errors.js` แปล `VALIDATION_ERROR` เป็นข้อความกลาง) และหน้าเว็บไม่ได้ตรวจชื่อว่าง/เวลาสลับกันก่อนส่ง
   - ข้อเสนอ: ตรวจชื่อและเวลาในหน้าเว็บก่อนส่ง หรือให้ `VALIDATION_ERROR` ใช้ข้อความจาก server
2. **M-15 — พบบั๊กแล้วแก้แล้ว (การใช้คีย์บอร์ด):** เดิม `BookingPage.renderLot()` สร้างผังใหม่ทั้งหมดทุกครั้งที่เลือกช่อง ปุ่มที่โฟกัสอยู่จึงถูกแทนที่ โฟกัสหลุดไปที่ `<body>` ผู้ใช้คีย์บอร์ดต้องกด Tab ไล่ใหม่
   - แก้: `renderLot()` จำ `data-slot` ของปุ่มที่โฟกัสอยู่ก่อนวาดใหม่ แล้วเรียก `focus()` ปุ่มเดิมหลังวาดเสร็จ (มีผลทั้งตอนเลือกช่องและตอนผังโหลดสถานะใหม่)
   - ทดสอบซ้ำผ่าน (16 พ.ย. 2026)
3. ช่องที่เต็มยังกดเลือกได้ตามที่ `SlotBay` ออกแบบไว้ (ให้ backend เป็นผู้ตัดสิน) หน้าเว็บจึงเตือนในสรุปการจองแทนการปิดปุ่ม
4. ทดสอบเคสลานเต็ม (M-11, M-12) บนโค้ดที่ backend ตอบ `ZONE_FULL` ด้วยสถานะ 409 — ข้อความในหน้าเว็บอ่านจาก code จึงเหมือนกันเมื่อเปลี่ยนเป็น 422
