## กติกาหลัก

- **ห้าม push ตรงเข้า `master`** — ทำงานทุกอย่างบน branch แยกเสมอ
- **ตั้งชื่อ branch:** `<area>/<type>-<short-desc>`
  - `area` = `fe` (frontend) หรือ `be` (backend)
  - `type` = `feat` | `fix` | `chore` | `docs` | `refactor`
  - เช่น `fe/feat-login-ui`, `be/fix-booking-overlap`
- **Commit message** ตาม Conventional Commits: `<type>(<scope>): <message>`
  - เช่น `feat(be): add parking slot reservation api`
- **ก่อน push ทุกครั้ง** ให้ `git pull --rebase origin master` ก่อนเสมอ
- **ห้าม commit secret** (.env, password, key ต่างๆ) — ใส่ไว้ใน `.gitignore` เสมอ
- ทุกงานต้องผ่าน **Pull Request + review อย่างน้อย 1 คน** ก่อน merge เข้า `master`
- แนะนำใช้ **Squash & Merge** เพื่อให้ history อ่านง่าย

## Workflow

```
git checkout master && git pull --rebase
git checkout -b <area>/<type>-<desc>

# ...ทำงาน...
git add .
git commit -m "<type>(<scope>): <message>"

git pull --rebase origin master   # ก่อน push ทุกครั้ง
git push -u origin <area>/<type>-<desc>
# เปิด PR -> รอ review -> merge เข้า master

# หลัง merge แล้ว ลบ branch ทิ้ง
git checkout master && git pull --rebase
git branch -d <area>/<type>-<desc>
git push origin --delete <area>/<type>-<desc>
```

## แก้ Conflict

```
git pull --rebase origin master
# แก้ไฟล์ที่ชนกัน (<<<<<<< / ======= / >>>>>>>)
git add <ไฟล์ที่แก้>
git rebase --continue
```

ถ้าพังมาก ใช้ `git rebase --abort` แล้วเริ่มใหม่

## กติกา Issue

- งานทุกอย่าง (ฟีเจอร์/บั๊ก) **เปิด Issue ก่อนเริ่มทำ** เพื่อ track และคุยกันในทีม
- ใช้ template ที่มีให้ (Bug report / Feature request) เวลากด New Issue
- ตั้งชื่อ branch/commit ให้ตรงกับ Issue ที่ทำ และใส่ `closes #<เลข issue>` ใน PR description เพื่อให้ปิด Issue อัตโนมัติตอน merge
- ใส่ label ให้ตรงประเภท (`bug`, `enhancement`) และ assign คนรับผิดชอบ

## กติกา Pull Request

- **PR ขนาดเล็ก** ทำทีละงาน อย่ารวมหลายฟีเจอร์ใน PR เดียว — รีวิวเร็ว conflict น้อย
- **ชื่อ PR** ให้สื่อความหมาย ตรงกับ branch/commit เช่น `feat(fe): login form + validation`
- **คำอธิบายใน PR ต้องมี:**
  - **What** — ทำอะไรบ้าง
  - **Why** — ทำไมต้องทำ (เกี่ยวกับ feature/issue ไหน)
  - **How to test** — ทดสอบยังไง
- Branch ต้อง **rebase กับ `master` ล่าสุดแล้ว** ก่อนขอ review (ไม่ควรมี conflict ค้าง)
- ต้องมี **อย่างน้อย 1 reviewer approve** ก่อน merge
- แก้ตามคอมเมนต์รีวิว → commit/push เพิ่มใน branch เดิม (ไม่ต้องเปิด PR ใหม่)
- Merge ด้วย **Squash & Merge** แล้วลบ branch ทิ้งทันที

## 1. โปรเจกต์นี้คืออะไร

เว็บให้นักศึกษา **ลงทะเบียนรถ** (ตรวจว่าเป็นนักศึกษา มธ. จริง) แล้ว **จองช่องจอดล่วงหน้า** จะได้ **บัตรจองที่มี QR Code** ไปสแกนตอนเข้าจอด

ระบบต้องกันเรื่องเหล่านี้ให้ได้ (มีเทสอัตโนมัติครบแล้วในฝั่ง Python):
- จองช่องเดียวกัน เวลาทับกัน → ต้องไม่ได้ (แม้ 2 คนกดพร้อมกัน)
- โซนเต็ม → ต้องบอกว่าเต็ม
- จองนอกเวลาเปิดทำการ (08:00–20:00) → ต้องไม่ได้

**เป้าหมายรอบนี้:** ทำหน้าเว็บ (Frontend) ใหม่ทั้งหมดให้สวยและแยกเป็นชิ้น ๆ เพื่อ Demo ให้อาจารย์ดู ส่วน Backend ระยะยาวจะเป็น Spring Boot + PostgreSQL (ทำทีหลัง ไม่ใช่รอบนี้)

## 2. ตอนนี้โค้ดอยู่สถานะไหน

พูดตรง ๆ ว่ามี **2 ชุด** อยู่ในโปรเจกต์ อย่าสับสน:

| ชุด | อยู่ที่ไหน | สถานะ | เราทำอะไรกับมัน |
|---|---|---|---|
| **หน้าเว็บเก่า** (สีฟ้า) | `backend-python/static/` | ใช้งานได้จริงครบทุกอย่าง | **ไม่ต้องแก้** ใช้เป็น "ตัวอย่าง" เปิดดูว่าเก่าทำยังไง แล้วย้ายลอจิกไปหน้าใหม่ |
| **หน้าเว็บใหม่** (ส้ม-แดง มธ.) | `frontend/` | โครงเสร็จแล้ว แต่ **ทุกชิ้นเป็นกล่องว่าง "TODO"** | **นี่คืองานของเรา** ช่วยกันเติมทีละชิ้น |
| **หลังบ้าน** (API + ฐานข้อมูล) | `backend-python/*.py` | เสร็จ ผ่านเทส 20 ข้อ | ใช้เป็น API ให้หน้าใหม่ต่อ **ห้ามแก้ logic** (ถ้าเจอบั๊กบอก PM) |

PM (คนวางโครง) ทำให้แล้ว: โฟลเดอร์ทั้งหมด, สีธีม, ระบบเปลี่ยนหน้า (router), ระบบ mock (ข้อมูลจำลอง), และไฟล์ว่างของทุกชิ้นพร้อม "สัญญา" บอกว่าต้องรับ/ส่งอะไร
**สิ่งที่เหลือ = เขียนเนื้อในของแต่ละชิ้น**

## 4. วิธีรันบนเครื่องตัวเอง

### วิธี A — ทำหน้าเว็บอย่างเดียว (ใช้ 95% ของเวลา)
ไม่ต้องมี backend ไม่ต้องลงอะไรเพิ่ม ใช้ข้อมูลจำลองในโฟลเดอร์ `frontend/js/api/mock/`

```bash
cd frontend
python3 -m http.server 8080
```
แล้วเปิด **http://localhost:8080/?mock=1#/booking**

- `?mock=1` = บอกให้หน้าเว็บใช้ข้อมูลจำลอง **อย่าลืมใส่** ไม่งั้นมันจะไปเรียก backend จริงที่ไม่ได้เปิดอยู่ แล้วขึ้น error
- `#/booking` = หน้าที่จะเปิด เลือกได้: `#/` หน้าแรก, `#/vehicle` ลงทะเบียนรถ, `#/booking` จอง, `#/ticket/PK-TEST2345` บัตรจอง, `#/history` ประวัติ
- เปิดจากไฟล์ตรง ๆ (ดับเบิลคลิก index.html) **ไม่ได้** เพราะเบราว์เซอร์ไม่ให้ใช้ ES modules ต้องผ่าน `http.server` เสมอ
- แก้โค้ดแล้ว กด Refresh ในเบราว์เซอร์ก็เห็นผลเลย (ไม่ต้อง build)

### วิธี B — ทดสอบกับ backend จริง (ตอนจะรวมงาน / Dev 3 ใช้บ่อย)
```bash
docker compose up --build
```
แล้วเปิด **http://localhost:8080** (ไม่ต้องใส่ `?mock=1`) nginx จะส่ง `/api/...` ไปหา Flask ให้เอง
> ✅ ผู้วางโครงทดสอบแล้วว่าใช้ได้จริง (หน้าเว็บขึ้น, `/api` วิ่งผ่าน nginx ไปถึง Flask, จอง A1 ได้ แล้วจองซ้ำถูกปฏิเสธ `SLOT_CONFLICT`) ปิดด้วย `docker compose down` · **ใช้พอร์ต 8080 เหมือนวิธี A จึงเปิดพร้อมกันไม่ได้** ถ้ามีปัญหาแจ้ง PM อย่าเสียเวลาแก้เอง

- ชิ้นงานรับข้อมูลทาง **props** แล้วส่งเหตุการณ์ออกทาง **ฟังก์ชัน** เช่น `onSelect(...)` ห้ามไปดึงข้อมูลเองจากเน็ต

## 9. กติกาของทีม (สั้น ๆ)

ฉบับเต็มอยู่ที่ `docs/CONVENTIONS.md` จำแค่ 6 ข้อนี้ก็พอ:

1. **ชิ้นงานรับข้อมูลทาง props ส่งเหตุการณ์ทาง callback** ห้ามไปหยิบ/แก้ส่วนอื่นของหน้า (`document.querySelector` ใน component = ผิด)
2. **เรียกเน็ต (`fetch`) ได้ที่เดียวคือ `js/api/client.js`** ชิ้นงานใน `components/` และ `features/` ห้าม import อะไรจาก `api/` มีแต่ `pages/` ที่คุยกับ `api/` ได้
3. **ห้ามพิมพ์รหัสสี `#xxxxxx` เอง** ใช้ `var(--ชื่อสี)` จาก `tokens.css` (อยากได้สีใหม่ → ขอ PM)
4. **ชื่อ class ขึ้นต้นด้วยชื่อชิ้นงาน** `.slot-bay`, `.slot-bay--booked`, `.slot-bay__label`
5. **ข้อความ error ภาษาไทยมาจาก `messageFor()` ใน `api/errors.js` ที่เดียว**
6. **Git:** 1 ใบงาน = 1 branch = 1 PR · ชื่อ branch `fe/feat-<ชื่อ>` (ตามกติกาทีมส่วนบนสุดของไฟล์) · ห้าม push เข้า `master` · ต้องมีเพื่อนอย่างน้อย 1 คน approve

**ตรวจกติกา 3 ข้อแรกก่อนส่ง PR ด้วย 3 คำสั่งนี้ (ต้องไม่มีผลลัพธ์ออกมา):**
```bash
grep -rn "fetch(" frontend/js --include='*.js' | grep -v "js/api/client.js"
grep -rnE "#[0-9a-fA-F]{3,8}\b" frontend/js frontend/css --include='*.js' --include='*.css' | grep -v tokens.css
grep -rn "import" frontend/js/components frontend/js/features --include='*.js' | grep "api/"
```

**ทุกชิ้นงานถือว่า "เสร็จ" เมื่อ:** ทำตาม Done when ในสัญญา · เปิดด้วย `?mock=1` ได้ ไม่มีตัวแดงใน Console · ที่ 375px ไม่มีแถบเลื่อนซ้ายขวา · ใช้คีย์บอร์ด (Tab/Enter) ได้ · ไม่มี `todo()` ค้างในไฟล์ · เพื่อนรีวิวผ่านแล้ว

## 11. ถามบ่อย / ติดปัญหา

**หน้าเว็บขึ้นแต่กล่อง "TODO: ชื่อชิ้นงาน" สีส้มประ?**
ปกติ นั่นคือชิ้นที่ยังไม่มีใครทำ พอเขียนเนื้อจริงแล้วกล่องนี้จะหายไป

**เปิดหน้าแล้วขึ้นว่างเปล่า / error ใน Console?**
1. เปิดผ่าน `http://localhost:8080` หรือยัง (ไม่ใช่ดับเบิลคลิกไฟล์)
2. ใส่ `?mock=1` หรือยัง
3. สะกดชื่อไฟล์ใน `import` ถูกไหม (ต้องมี `.js` ต่อท้าย และ path ถูกระดับ `../`)

**`import` ผิดแล้วหน้าพังทั้งหน้า?** เบราว์เซอร์จะบอกใน Console ว่าไฟล์ไหนหาไม่เจอ ดูบรรทัดแรกที่เป็นสีแดง

**ต้องการสีใหม่ / ขนาดตัวอักษรใหม่?** ห้ามเพิ่มเองในไฟล์ตัวเอง ไปบอก PM ให้เพิ่มใน `css/tokens.css` ทุกคนจะได้ใช้ตรงกัน

**ต้องแก้ไฟล์ของคนอื่น (เช่น อยากได้ปุ่มแบบใหม่จาก Dev 1)?** บอกเจ้าของไฟล์ให้แก้ หรือขอเขาเปิด PR เล็ก ๆ อย่าแก้ข้ามกัน จะ merge ชนกัน

**จะรู้ได้ไงว่าอีกชิ้นรับ props อะไร?** เปิดไฟล์ชิ้นนั้นดูบรรทัด 1-8 ที่เป็นสัญญา (ชนิดข้อมูลเขียนไว้ครบ) ถ้าอยากเปลี่ยนสัญญา แจ้งทีมก่อน เพราะคนอื่นอาจใช้อยู่

**เจอบั๊กใน backend (Python)?** ไม่ต้องแก้ แจ้ง PM เทส 20 ข้อใน `backend-python/tests/` เป็นตัวยืนยันว่ากฎจองถูกต้อง

**ฟีเจอร์ลงทะเบียนรถจะเรียก backend จริงตอนไหน?** ยังไม่ใช่รอบนี้ รอบนี้ใช้ mock ให้ครบ flow สำหรับ Demo ทีม backend (Spring Boot) จะทำตาม contract ใน `frontend/js/api/vehicles.js` ทีหลัง
